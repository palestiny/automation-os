# Design Patterns Learning Log

## Rule

We learn patterns when the project encounters the problem they solve.

We do not force patterns into the codebase.

## Pattern Record Template

For every important pattern:

### Problem

What problem appeared?

### Context

Where does the problem exist in AutoReel AI?

### Candidate Solutions

What alternatives were considered?

### Pattern

Which pattern was selected?

### Why

Why is it appropriate?

### Trade-offs

What complexity does it introduce?

### Implementation

Where is it implemented?

### Learning

What should Khaled remember for future systems?

## Current Candidates

- State: execution lifecycle
- Strategy: retry policies / interchangeable algorithms
- Registry: capability lookup
- Factory: plugin construction
- Adapter: external providers
- Command: executable operations
- Dependency Injection: application composition

These are learning targets, not automatic implementation requirements.
