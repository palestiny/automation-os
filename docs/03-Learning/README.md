# Learning Program

This project is deliberately being used as an enterprise software learning environment.

## Curriculum

### Architecture

- Modular Monolith
- Clean Architecture
- Domain Driven Design
- dependency direction
- bounded responsibilities
- architecture decision records

### Design Patterns

Patterns should be learned through real problems in this project.

Potential patterns include:

- Strategy
- Factory
- Registry
- Adapter
- Command
- State
- Template Method
- Dependency Injection
- Repository
- Observer/Event-driven patterns

A pattern is not added merely because it exists. We first identify the problem, then evaluate whether the pattern is justified.

### Engineering

- requirements;
- issue management;
- Git branches;
- commits;
- pull requests;
- code review;
- automated testing;
- CI/CD;
- documentation;
- release/versioning;
- observability;
- error handling;
- retry policies.

### Git / GitHub

For every important Git command, learn:

- what it changes;
- why we use it;
- what state it operates on;
- how to undo it safely.

## Teaching Rule

Never optimize only for speed.

Prefer understanding + correct implementation + documented reasoning.
